# 夜间 AI 的两只时钟

有些工作即使要等上几个小时才得到答案，仍然有价值。为第二天早晨准备报告、提出软件修复方案，或审阅一份长文档，都容得下等待。对将 AI 集成到软件中的人来说，这种时间弹性带来一个经济问题：如果服务有更多时间作答，这项工作的成本能降低多少？

开发 GPT 系列 AI 模型的 OpenAI，如今提供了一种具体方式来进行这种权衡。它的后台处理选项允许模型请求使用更长的完成时间窗口，换取更低的模型 token 费率。八小时窗口听起来尤其适合夜间工作：晚上提交任务，早晨领取结果。

但要弄清“结果”指什么，还需要仔细看一看。AI 响应可以是一份完成的答案，也可以是要求获取信息的请求；周边软件必须先取回这些信息，工作才能继续。两者都算响应，但整个任务所处的阶段并不相同。

这一区别很重要，因为夜间 AI 涉及两只相关的时钟。一只衡量模型响应何时到达，另一只衡量有用且完整的成果何时到达。

OpenAI 于 2026 年 11 月 17 日发布的两个新模型，为这个问题增添了新的选择。GPT-6.2 Sol 是其面向日常编程和智能体工作流程的高效模型。智能体工作流程指的是软件借助 AI 模型执行任务的一系列步骤。GPT-6.2 Astra 则是其面向高难度推理和编程任务、价格更高的前沿模型。

应用程序通过 API 使用这些模型。API 是一个结构化的入口，让一个程序能够请求另一项服务完成工作。开发者可以使用 OpenAI 的 Responses API 向模型发送指令、获取回答，并处理模型提出的工具使用请求。例如，某个工具可能用于查找文档。应用程序执行查找，再把找到的信息交还给模型。

Responses API 还支持后台模式。请求可以持续运行，应用程序则检查进度，稍后再取回响应。这样，应用程序就能管理需要等待一段时间才能得到回答的工作。

对初次接触这些系统的读者来说，理解这种分工很重要。模型生成响应。应用程序管理更长的工作过程：提供信息、运行工具、发出后续请求、检查结果并交付完成的工作。整套安排是否有用，取决于这些环节如何协同。

价格说明了运营者为何会关注等待时间。OpenAI 按 token 收费；token 是模型处理或生成的文本小单元。输入 token 对应发送给模型的内容，输出 token 对应模型生成的内容。

对于较短的请求，按 Standard 费率计算，Sol 每百万输入 token 收费 2 美元，每百万输出 token 收费 10 美元。Astra 对应的价格分别为 8 美元和 40 美元，均为 Sol 对应费率的四倍。输入 token 超过 272,000 的请求适用更高的价格档位：输入和缓存输入费率翻倍，输出费率则提高到较短请求费率的 1.5 倍；这些费率适用于整个请求。

这些是起始价格。OpenAI 的后台模式文档介绍了两种目前处于公开测试阶段的完成时间窗口：两小时和八小时。两小时选项的模型 token 费率比 Standard 低 30%；八小时选项低 40%。

延迟成了定价因素。日程灵活的运营者可以接受更长的响应窗口，以较低费率使用模型。文档明确说明的收益是价格下降；更长的窗口会对答案质量产生什么影响，仍是一个有待实证回答的问题。

关于时间的措辞同样值得留意。OpenAI 表示，API 以在所选窗口内完成**初始响应**为目标，计时从它接受请求时开始。这针对的是某一次特定响应。由应用程序管理的完整任务则有更长的时间线。

OpenAI 文档中的例子清楚地说明了这一区别。应用程序发送一个完成时间窗口为八小时的请求。模型的第一次响应要求应用程序查找一份文档。应用程序完成查找，然后在后续请求中提交取回的信息。

此时，第一次响应已经到达，但更大的任务仍在继续。应用程序还要管理后续的一切：进一步交互、检查、问题恢复和最终交付。如果应用程序复用完成时间窗口、续接 ID、模型和项目，符合条件的后续请求也可以享受折扣。这些条件使工作过程继续时仍符合折扣资格；初始响应目标的适用范围则仍然明确。

可以想象一家夜间营业的面包房承诺，第一盘烘焙食品会在早晨出炉。要把一份完整的早餐送到家，还需要打包食物、安排司机、核对地址，并在道路封闭时寻找其他路线。

在这个比喻中，第一盘出炉的食品是模型响应。早餐送达正确地址，才是完成的工作流程。第一盘何时出炉会影响配送，而配送还依赖后续多个环节。即使第一盘准时出炉，接下来的路程仍可能困难重重。

同样的区别赋予了八小时 AI 窗口实际意义。如果初始响应包含完整答案，应用程序可能已接近交付。如果响应要求提供文档，就需要开启下一轮交互。核验可能带来修改，工具调用失败可能需要恢复。协调这些工作是应用程序的责任；文档规定的窗口提供的是响应时间目标，而非端到端的交付保证。

这也改变了折扣的解读方式。模型 token 费率降低 40%，意味着账单中的一个组成部分变便宜了。但产出有用结果的成本还可能包括工具费用、重复请求、重试、应用程序的计算开销和人工审阅。失败的尝试也会消耗资源。

因此，Astra 较高的 token 价格和 Sol 较低的 token 价格，确定的是按所述费率购买模型输出的成本。哪个模型能以更低成本产出成功交付的成果，取决于完整任务。OpenAI 的基准测试对比和早期测试者的说法，是在各自所述条件下由提供方给出的证据。要衡量某个具体应用程序的交付成本，还需要该应用程序自身的数据。

对 RobinOS 来说，针对这些新后台时间窗口的受控比较仍是未来的工作。每份成功交付成果的成本、人工介入时间、故障恢复负担，以及能够有效无人值守运行的时长，都有待测量。

有意义的比较应固定一项真实任务，分别用 Sol 和 Astra 执行，并持续追踪到成功交付。重要的观测结果包括总成本、人工协助所花的分钟数，以及工作过程中的某个环节失败时会发生什么。这才能把模型价格和响应时间与运营者的实际目标联系起来。

11 月 17 日的发布带来了新的模型选择，后台时间窗口则提供了响应时间与 token 费率之间的明确交换。夜间工作的更大价值，取决于从请求被接受到成果交付完成的整个过程。

在判断 AI 能否有效自主工作时，运营者该看哪只时钟：在模型第一次响应时停下的那只，还是在工作成功交付时才停下的那只？
