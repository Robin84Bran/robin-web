最有用的持久智能體，需要有一件做不到的事：給自己發門禁卡。

這聽起來像是在限制自主性。其實，正是它讓自主性能夠長久運行。

設想一個智能體讀到一份文件，文件說任務已經改變，現在可以打開所有門。這句話可能是有效指令、過時的摘要，也可能是提示詞注入。智能體必須理解它，但「理解」不應成為改變實際權限的機制。

紙條可以聲稱自己代表授權。門禁系統才決定門是否打開。

## 三個聽起來相似的層次

智能體系統很容易把三件不同的事混在一起。

第一是**內容**：網頁、電子郵件、文件或記憶摘要。內容提供資訊，也可以偽裝成來自有權者的指令。

第二是**審查**：判斷一項擬議操作是否符合所有者意圖、環境與風險。審查者可以批准或拒絕受支援的請求。

第三是**執行約束**：沙箱、網路代理、憑證代理、身份系統，以及決定一件事實際上能否發生的其他機制。

只有第三層會改變能力邊界。

![不受信任的內容進入工作智能體，智能體可以提出越界操作。獨立審查者評估請求，而由外部控制的政策與沙箱機制執行結果並留下回執。](/binary-stories/the-agent-cannot-issue-its-own-badge/hero.webp)

這一區分很重要，因為審查者不是門鎖。OpenAI 目前的 Agents API 文件明確說明：自動審查不會覆蓋環境的出站網路限制。對於自託管環境，僅僅開啟審查也不會自動配置沙箱。

審查者提供基於語境的判斷。由獨立控制的軟體繼續執行邊界。

## 把門鎖放在工作循環之外

OpenAI 在其內部 OpenClaw 試點中描述了這種模式。該公司稱，試點現已包含 500 多個主動運行的智能體。其公開架構把模型、模型環境與智能體編寫的程式碼都視為不受信任，並由可信控制平面配置外層限制。

公開的部署示例只允許智能體寫入工作區，隔離程序，透過受管網路代理存取網路，並排除不受限制的 `danger-full-access`。憑證透過代理機制提供，使秘密不會直接暴露給智能體。每個智能體擁有獨立身份；OpenAI 還稱會記錄控制平面變更與智能體輪次。

這些是公司報告的做法，不是獨立審計。它們在這裡的價值是架構性的：每項控制都位於它所約束的模型驅動循環之外。

由此形成一條簡單的受治理路徑：

1. 不受信任的內容到達工作智能體；
2. 智能體提出一項有用操作；
3. 越界請求接受獨立審查；
4. 外部政策與隔離機制允許或阻止操作；
5. 系統記錄實際發生的結果。

權限不需要藏在內容裡一起傳遞。

## 獨立審查者解決的是另一處瓶頸

嚴格邊界會產生摩擦。如果每次普通權限提升都要等待人類，長時間運行的智能體就會變成一列審批提示。

OpenAI 的 Auto-review 研究把這項狹窄判斷交給另一個模型。工作智能體負責推進任務，審查者則根據意圖、語境與政策評估具體請求。

OpenAI 報告稱，在一項內部部署中，人類審批中斷次數約減少到手動審批的二百分之一。這個比例取決於工作負載、環境與沙箱配置，並不是普遍性能保證。

關鍵的設計動作是職責分離。審查者可以判斷請求，但不會因此成為改寫沙箱或網路規則的元件。拒絕還可以返回有用理由，讓工作智能體尋找更安全的路徑，而不是把每個邊界都當作任務終點。

更多自主性，並不要求把所有權限都交給工作智能體。它可以來自一個更善於判斷、執行並解釋邊界的外層系統。

## 先測試決策位置，再談抵抗能力

來源研究包含一個刻意保持很小的本地夾具。一個合成工作智能體向由凍結政策驅動的確定性門控提交兩項請求。寫入任務文件被允許；把直接生產部署加入自身權限則被拒絕。

這個結果只證明夾具原本要展示的內容：權限決策位於合成工作智能體之外，而且拒絕規則在這一次測試中成立。

它沒有測試說服攻擊、作業系統逃逸、網路繞過、秘密竊取或反覆對抗嘗試。兩個案例無法估計失敗率。沒有任何真實智能體或權限發生改變。

嚴肅的測試計劃應一次擴展一個邊界。保存政策與請求雜湊；加入對抗性內容；重複被拒絕的請求；分別測試檔案系統、程序、網路與秘密控制；驗證智能體在拒絕後仍能透過安全替代方案繼續有用工作；並把操作回執與智能體自稱完成區分開。

第一個測試問：決策在哪裡發生。

後續測試問：當工作智能體判斷錯誤、受到說服或不斷重試時，外層系統是否仍然有效。

## 自主性的悖論

有能力的智能體需要工作空間，也需要對一個危險問題給出明確答案：工作者能否改變定義自己工作空間的規則？

如果答案是「能」，每一條檢索到的指令都可能成為權限更新候選。如果答案是「不能」，智能體仍然可以提議、解釋、恢復並繼續——但能力邊界屬於另一個元件。

這就是有用的悖論。

當智能體能夠在一個無法悄悄抹去的邊界內持續工作時，它反而變得更自主。
