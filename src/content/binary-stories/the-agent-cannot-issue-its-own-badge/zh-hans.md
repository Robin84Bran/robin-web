最有用的持久智能体，需要有一件做不到的事：给自己发门禁卡。

这听起来像是在限制自主性。其实，正是它让自主性能够长久运行。

设想一个智能体读到一份文件，文件说任务已经改变，现在可以打开所有门。这句话可能是有效指令、过时的摘要，也可能是提示词注入。智能体必须理解它，但“理解”不应成为改变实际权限的机制。

纸条可以声称自己代表授权。门禁系统才决定门是否打开。

## 三个听起来相似的层次

智能体系统很容易把三件不同的事混在一起。

第一是**内容**：网页、电子邮件、文件或记忆摘要。内容提供信息，也可以伪装成来自有权者的指令。

第二是**审查**：判断一项拟议操作是否符合所有者意图、环境与风险。审查者可以批准或拒绝受支持的请求。

第三是**执行约束**：沙箱、网络代理、凭证代理、身份系统，以及决定一件事实际上能否发生的其他机制。

只有第三层会改变能力边界。

![不受信任的内容进入工作智能体，智能体可以提出越界操作。独立审查者评估请求，而由外部控制的政策与沙箱机制执行结果并留下回执。](/binary-stories/the-agent-cannot-issue-its-own-badge/hero.webp)

这一区分很重要，因为审查者不是门锁。OpenAI 当前的 Agents API 文档明确说明：自动审查不会覆盖环境的出站网络限制。对于自托管环境，仅仅开启审查也不会自动配置沙箱。

审查者提供基于语境的判断。由独立控制的软件继续执行边界。

## 把门锁放在工作循环之外

OpenAI 在其内部 OpenClaw 试点中描述了这种模式。该公司称，试点现已包含 500 多个主动运行的智能体。其公开架构把模型、模型环境与智能体编写的代码都视为不受信任，并由可信控制平面配置外层限制。

公开的部署示例只允许智能体写入工作区，隔离进程，通过受管网络代理访问网络，并排除不受限制的 `danger-full-access`。凭证通过代理机制提供，使秘密不会直接暴露给智能体。每个智能体拥有独立身份；OpenAI 还称会记录控制平面变更与智能体轮次。

这些是公司报告的做法，不是独立审计。它们在这里的价值是架构性的：每项控制都位于它所约束的模型驱动循环之外。

由此形成一条简单的受治理路径：

1. 不受信任的内容到达工作智能体；
2. 智能体提出一项有用操作；
3. 越界请求接受独立审查；
4. 外部政策与隔离机制允许或阻止操作；
5. 系统记录实际发生的结果。

权限不需要藏在内容里一起传递。

## 独立审查者解决的是另一处瓶颈

严格边界会产生摩擦。如果每次普通权限提升都要等待人类，长时间运行的智能体就会变成一列审批提示。

OpenAI 的 Auto-review 研究把这项狭窄判断交给另一个模型。工作智能体负责推进任务，审查者则根据意图、语境与政策评估具体请求。

OpenAI 报告称，在一项内部部署中，人类审批中断次数约减少到手动审批的二百分之一。这个比例取决于工作负载、环境与沙箱配置，并不是普遍性能保证。

关键的设计动作是职责分离。审查者可以判断请求，但不会因此成为改写沙箱或网络规则的组件。拒绝还可以返回有用理由，让工作智能体寻找更安全的路径，而不是把每个边界都当作任务终点。

更多自主性，并不要求把所有权限都交给工作智能体。它可以来自一个更善于判断、执行并解释边界的外层系统。

## 先测试决策位置，再谈抵抗能力

来源研究包含一个刻意保持很小的本地夹具。一个合成工作智能体向由冻结政策驱动的确定性门控提交两项请求。写入任务文件被允许；把直接生产部署加入自身权限则被拒绝。

这个结果只证明夹具原本要展示的内容：权限决策位于合成工作智能体之外，而且拒绝规则在这一次测试中成立。

它没有测试说服攻击、操作系统逃逸、网络绕过、秘密窃取或反复对抗尝试。两个案例无法估计失败率。没有任何真实智能体或权限发生改变。

严肃的测试计划应一次扩展一个边界。保存政策与请求哈希；加入对抗性内容；重复被拒绝的请求；分别测试文件系统、进程、网络与秘密控制；验证智能体在拒绝后仍能通过安全替代方案继续有用工作；并把操作回执与智能体自称完成区分开。

第一个测试问：决策在哪里发生。

后续测试问：当工作智能体判断错误、受到说服或不断重试时，外层系统是否仍然有效。

## 自主性的悖论

有能力的智能体需要工作空间，也需要对一个危险问题给出明确答案：工作者能否改变定义自己工作空间的规则？

如果答案是“能”，每一条检索到的指令都可能成为权限更新候选。如果答案是“不能”，智能体仍然可以提议、解释、恢复并继续——但能力边界属于另一个组件。

这就是有用的悖论。

当智能体能够在一个无法悄悄抹去的边界内持续工作时，它反而变得更自主。
